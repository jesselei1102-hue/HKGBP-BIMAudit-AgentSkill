## 1. 要做什么

给 Model Audit 交付包加一个前端：审核时在对话里弹出窗口，用户在窗口里选要做哪些检查；分析完后在窗口里看结果总览，并在那里完成确认关口。

### 1.1 已定的选择（来自你的回答）

| 问题 | 选择 |
| --- | --- |
| 用不用 MCP Apps | 用。Claude Code 能显示 MCP Apps |
| 放在哪个 server | 方案 A：交付包里自己的独立 server，不依赖别人的 server（长期要求） |
| 窗口读不读 Revit | 不读。窗口只负责选检查、看结果 |
| 结果总览和确认关口 | 总览就是确认关口 |
| 读数核对 | 默认每条读数都标过「对 / 错」才能确认；也可以不核对直接出报告，但要一直保留提醒 |
| 待定（UNCLEAR） | 提示用户自己检查 |
| 运行环境 | 接受多一个 Node.js 要求 |

### 1.2 不做什么

- 窗口不连 Revit，不改模型，不取模型数据。
- 不另写一套执行流程：取数、分析、出报告仍按 `RUN.md` 和现有 skill，由 agent 做。
- 不替代 revit-mcp / mcp-servers-for-revit。

## 2. 结构

```
model-audit/
  app/                 新增：gbp-audit MCP server + 窗口（Ultraviolet 模板）
    src/               server：工具、读审核文件夹、写确认记录
    app/               窗口：选检查、总览
    test/  dev/        单元测试、模拟宿主
  tasks.json           新增：任务清单（组、编号、名称、一句话说明）
  tools/  report/      现有 Python；改动见 §6
```

- server 由 `Design Theme\template` 复制而来，Node / TypeScript，stdio。
- 审核时同时连两个 server：Revit MCP（取数）+ `gbp-audit`（窗口）。只连 Revit MCP 也能审核，只是没有窗口，用 `RUN.md` §7 的文字指令。
- 审核文件夹根目录：设置项（环境变量 `GBP_AUDIT_RUNS` 或启动参数），默认交付包旁的 `model-audit-runs/`。server 只读写这个目录和交付包，拒绝 `..` 等越界路径。

## 3. 流程

```
用户：「做 GBP 审核」
  → agent 调 choose_checks → 窗口 ①
① 用户勾选任务，选「新开审核」或「并入已有审核」，点「运行 N 项」
  → 窗口往对话发一句指令（RUN.md §7 的短指令 + 任务清单 + 审核文件夹）
agent 用当前的 Revit MCP 取数，跑分析脚本（同现在）
  → 调 show_overview(run) → 窗口 ②（总览 = 确认关口）
② 用户核对读数，点「确认，出报告」/「退回重读」/「不核对直接出报告」
  → save_gate 写 gate-confirmation.json，窗口往对话发对应指令
agent 出报告 → 调 show_overview(run) → 窗口 ③（总览 + 报告位置）
```

宿主不支持窗口往对话发消息时：窗口显示那句指令和复制按钮，用户自己贴进对话。

## 4. 窗口

外观沿用 Ultraviolet 外框（顶部统计、编号分页、表格、底部主按钮），只用主题里的颜色和组件。

### 4.1 窗口 ①：选检查

- 分页按执行分组：01 G1 采光通风、02 G2 房间用途、03 G3 面积、04 G4 图纸、05 G5 清单与模型健康。
- 每行：TL 编号、任务名、一句话说明。可一键勾整组，可按编号 / 名称搜索。
- 有的任务在几个组里都有（例：V08、V10、V11 在 G3 和 G4，A1 在 G2 和 G5）：每个组页都显示，并注明「也在 Gx」；勾一处即全部勾上，指令里写明要跑的每一组。
- 「新开审核」或「并入已有审核」（RUN.md §6c 的按任务单独跑再合并）；已有审核从审核文件夹列出。
- 底部主按钮：「运行 N 项」。

### 4.2 窗口 ②：总览 = 确认关口

- 顶部统计：检查数、不通过、待定（「N 项需自行检查」）、待核读数。
- 01 任务：每个任务一行，通过 / 不通过 / 待定数；点开看每条检查的预期、实际、条文依据。
- 待定的每一条标「需自行检查」，并写该看哪里（取自检查结果的 `fix`）。待定不挡确认，总览和报告里一直显示。
- 02 待核读数：每条一张卡——截图、读到的值、图纸、判定；用户标「对 / 错」，标错时可写一句原因。没有截图的照现有规则标「无截图」。
- 03 数据问题：`-INPUT` 待定项（缺哪项输入、怎么补）和数据质量警告。
- 底部按钮：

| 状态 | 主按钮 | 发给对话 |
| --- | --- | --- |
| 全部读数标「对」 | 确认，出报告 | 已确认，出报告 |
| 有读数标「错」 | 退回重读 | 错的几条和原因，请重读、重跑分析，再显示总览 |
| 任何时候（次要按钮） | 不核对直接出报告 | 出报告；未核对和标错的读数照 `gate-confirmation.json` 写进报告 |

### 4.3 窗口 ③：出完报告

同总览，多一栏「报告」：BIM 版、AP 版总报告和各组报告的路径。能否在窗口里直接打开本机 HTML 取决于宿主；打不开就显示路径和复制按钮。

## 5. Server 工具与数据

| 工具 | 谁调 | 作用 |
| --- | --- | --- |
| `choose_checks` | agent | 弹出窗口 ①；带 `tasks.json` 和已有审核文件夹列表 |
| `show_overview(run)` | agent | 弹出窗口 ② / ③；读该次审核的结果 |
| `get_crop(run, file)` | 只给窗口 | 按需取一张截图（base64），避免一次回传过大 |
| `save_gate(run, marks, mode)` | 只给窗口 | 写 `<run>/gate-confirmation.json` |

- 「只给窗口」的工具对 agent 隐藏（`_meta.ui.visibility: ["app"]`）。
- `show_overview` 读：各组分析 JSON（`checks`、`summary`、`readings`；含 `--tasks` 跑出的部分结果）、`audit-results.json`、报告文件。G1（`tools/s14_lv/`）的输出格式和 G2–G5 不同，实施计划第一步先核对，再定读法。
- `gate-confirmation.json`：

```json
{
  "mode": "confirmed | unreviewed",
  "saved": "<ISO 时间>",
  "readings": [{"key": "...", "sheet": "...", "mark": "ok | wrong | none", "note": "..."}]
}
```

  不碰现有的 `decisions.json`（那是给 AP 的问题）。

- `tasks.json`：`[{ "task": "AUD-S10", "tl": "TL-S10", "name": "...", "summary": "...", "groups": ["G2"] }]`。

## 6. 现有 Python 的改动

- `tools/common/build_results.py`：读 `<run>/gate-confirmation.json`（有就读），把核对状态带进 `audit-results.json`。
- `report/render_report.py`：有未核对或标错的读数时，报告顶部加一条提醒，并列出这些读数；标错的写「操作者认为有误」。
- 没有 `gate-confirmation.json`（文字指令跑的审核）：照现在的行为，不加提醒。

## 7. 出错处理

| 情况 | 窗口的做法 |
| --- | --- |
| 审核文件夹不存在 / 还没有分析结果 | 空状态，写明缺什么 |
| JSON 坏了 | 写明哪个文件、什么错；不显示半套结果 |
| 截图文件不在 | 该读数标「无截图」 |
| 越界路径 | server 拒绝，窗口显示错误 |
| 宿主不能从窗口发消息 | 显示指令 + 复制按钮 |
| `save_gate` 写入失败 | 标记保留在窗口里，显示错误，可重试 |
